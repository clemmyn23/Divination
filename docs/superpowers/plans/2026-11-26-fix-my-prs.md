# Fix My PRs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Fix button on each of the owner's PRs that is failing CI or has merge conflicts: Claude edits files in a throwaway worktree, and the tool's own code commits and pushes to that PR's branch.

**Architecture:** A new `src/sources/github/fix/` holds pure rules, an attempts record, git helpers, log reading, the Claude run and one orchestrator (`fixOne`). The collector attaches each PR's fix state, so the panel only draws. The server and a `fix` command are the only two ways a fix starts.

**Tech Stack:** Node 24 running TypeScript directly, ESM, `node:test`, the `git`, `teamcity` and `claude` command-line tools through `ctx.exec`. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-26-fix-my-prs-design.md`

## Global Constraints

- Test-first: every step that adds behaviour starts with a failing test that is run and seen to fail.
- Run one file with `node --test src/path/file.test.ts`; the whole suite with `pnpm test`; types with `pnpm typecheck`.
- The only writes to GitHub are `git push origin HEAD:refs/heads/<head branch>` of the pressed PR, never forced. No comment, review, reaction, approval or merge.
- Claude never runs git, a shell, a connector or the web. Its file tools are confined to the worktree.
- Git hooks are off for the fix's commit and push.
- A worktree is removed however a fix ends.
- Log contents and file contents never reach `ctx.log` (the events file or the activity view). Step names, check names and file paths may.
- A fix starts only from `POST /api/fix` or the `fix` command. Nothing starts one on a timer or a refresh.
- No Claude or co-author line in any commit, the fix's or this plan's.
- Docs and tests use invented names only (`acme/monolith`, `ABC-101`). No real repository, person, team or host.
- Messages are plain, in the tool's existing style. No token, log text or file text in an error.
- Commit after each task with a `feat:`, `test:` or `docs:` message. Do not push.

## Review Focus

- **A head branch with slashes** (`me/ABC-101-add-writer`): the fetch, the worktree name and the push refspec must all still work. Test in Task 6.
- **The clone's `origin` in each form** (`git@host:owner/repo.git`, `https://host/owner/repo`, `ssh://git@host/owner/repo.git`, wrong host, wrong repo). Test in Task 3.
- **An attempts file that is missing, empty or hand-edited into the wrong shape**: read as no attempts, never a crash. Test in Task 4.
- **A log that is huge or holds multi-byte text**: cut to the byte limit without splitting a character. Test in Task 3.
- **Claude's summary with line breaks, quotes or a leading dash**: becomes one tidy commit message, passed as a single argument. Test in Task 3.

## Rulings made while planning

- **The fix state is attached when GitHub is collected, not when the page is drawn.** A panel receives only data and the view, and has no way to read the attempts file. Every fix ends with a collect, so the page is as current as the design asks. Whether a PR is old or ticked off is still decided when the page is drawn and when Fix all is pressed.
- **Hooks are switched off with an empty hooks folder** (`-c core.hooksPath=<empty dir>` plus `--no-verify`), which works on every platform, rather than `/dev/null`.

```ts
export interface Attempt {
  at: number;
  what: "ci" | "conflicts";
  checks: string[];
  /** The head commit the attempt started from. */
  startSha: string;
  /** The commit it pushed, when it pushed one. */
  pushedSha?: string;
  outcome: "pushed" | "gave-up" | "failed";
  /** Claude's summary, or why it stopped. Plain words for the PR's line. */
  text: string;
  /** False when the attempt ended before Claude was asked. Only true ones count toward the limit. */
  ranClaude: boolean;
  costUsd?: number;
}
export interface FixState {
  /** A Fix button belongs on this PR now. */
  can: boolean;
  /** Attempts in a row have reached `github.fix.maxAttempts`. */
  spent: boolean;
  /** The latest attempt on the current chain. */
  last?: { at: number; outcome: Attempt["outcome"]; text: string };
}
```
  and `MyPull` gains `fix?: FixState`.
- Produces, in `attempts.ts`:
  - `attemptsPath(ctx: Context): string` — `<out>/fix/attempts.json`
  - `readAttempts(ctx: Context): Record<string, Attempt[]>`
  - `recordAttempt(ctx: Context, key: string, attempt: Attempt): void`
  - `chain(attempts: Attempt[], headSha: string): Attempt[]` — oldest first
  - `ownerSha(attempts: Attempt[], headSha: string): string`
  - `fixState(pr: { key: string; repo: string; draft: boolean; ci: Ci; conflicts: boolean; headSha: string }, fix: Config["github"]["fix"], attempts: Attempt[]): FixState`

- [ ] **Step 1: Write the failing tests.** Helper: `const a = (startSha: string, pushedSha: string | undefined, over: Partial<Attempt> = {}): Attempt => ({ at: 1, what: "ci", checks: [], startSha, ...(pushedSha ? { pushedSha } : {}), outcome: pushedSha ? "pushed" : "gave-up", text: "t", ranClaude: true, ...over })`.
  - "the chain is the unbroken run of attempts ending at the current head":
    - `chain([a("s0","s1"), a("s1","s2")], "s2")` has length 2;
    - `chain([a("s0","s1"), a("s1","s2")], "mine")` is `[]` (the owner pushed);
    - `chain([a("s0","s1"), a("s1", undefined)], "s1")` has length 2 (a give-up stays on the same head);
    - `chain([a("s0","s1"), a("x","y"), a("s1", undefined)], "s1")` has length 1 (an attempt on another head breaks it).
  - "the owner's commit is where the chain started": `ownerSha([a("s0","s1"), a("s1","s2")], "s2")` is `"s0"`; with head `"mine"` it is `"mine"`; `ownerSha([], "h")` is `"h"`; `ownerSha([a("s1", undefined)], "s1")` is `"s1"`.
  - "a PR can be fixed when it is failing or conflicted, has a clone, and has attempts left": with `fix = { ...defaults, clones: { "acme/monolith": "/w" } }`, a failing PR gives `{ can: true, spent: false }`; a conflicted one too; a draft, a passing unconflicted PR, and a PR in a repo with no clone each give `can: false, spent: false`.
  - "two attempts in a row use it up, and only attempts where Claude ran count": two `ranClaude: true` attempts on the chain give `{ can: false, spent: true, last: {...} }`; one of them `ranClaude: false` gives `can: true`.
  - "the last attempt on the chain is reported, and none when the owner has pushed since": `last` equals `{ at, outcome, text }` of the newest chain attempt; with a head the chain does not reach, `last` is absent and `can` is true again.
  - "attempts are kept per PR and survive a bad file": `recordAttempt` twice then `readAttempts` returns both in order under the key; with the file holding `"[]"`, `"not json"` or `{"k": "x"}`, `readAttempts` returns `{}` (or drops the bad entry) and never throws.
